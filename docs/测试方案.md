# AgentNet 端到端测试方案 (用户视角)

> 与 `docs/DEV_DOCUMENTS.md` 配套。本文档给出"如何在用户视角下验证 AgentNet MVP 全链路"的完整操作步骤与测试矩阵。

## 0. 环境前置

- **Docker Desktop**（用于本地 PostgreSQL）：https://www.docker.com/products/docker-desktop/
- **Python 3.11+**（已验证 3.14 + pip 工作正常；推荐 3.12 或 3.11 以避免 greenlet 边界问题）
- **LLM API key**（任一）：
  - DeepSeek：https://platform.deepseek.com/ （推荐，国内快 + 注册赠额度）
  - 智谱 GLM：https://open.bigmodel.cn/
  - 通义千问：https://dashscope.aliyun.com/

> 没有 key 也能跑通：见 §7 "Mock 路径"。

## 1. 三种启动路径速查

| 路径 | 需 Docker | 需真 LLM key | 验证范围 |
|---|---|---|---|
| **A. Mock 端到端** | ✗ | ✗ | 全部业务编排逻辑（不含 DB 落盘） |
| **B. 完整连通** | ✓ | ✓ | 全栈：DB + LLM + 下游 HTTP + 治理 |
| **C. SQLite 折中** | ✗ | ✓ | A + 真实 DB 落盘 |

> 用户选择：**B（完整连通）** + **12 项测试全验证**。

## 2. 新增文件（执行阶段创建）

| 文件路径 | 作用 |
|---|---|
| `tests/echo_server.py` | 假扮专家 Agent；多路径 echo，触发各类错误码 |
| `tests/smoke.ps1` (Windows) / `tests/smoke.sh` (Linux) | 把 12 项测试串成一行跑 |

### 2.1 echo_server.py 暴露端点

```
POST /api/v1/chat     -> 200，echo sub_query              (默认健康 + 单步直跳 + deep_plan)
POST /api/v1/fail5xx  -> 502                              (触发 §2.2 归一)
POST /api/v1/bad4xx   -> 400                              (触发 §2.2 归一)
POST /api/v1/slow     -> sleep 后回 200                   (触发 §2.2 timeout 归一)
GET  /health          -> 默认 200；通过环境变量可切常 500  (用于 §5.2 健康摘除)
```

监听 `127.0.0.1:9001`。一个 echo server 覆盖 12 项测试的全部下游响应。

## 3. 操作步骤（命令清单）

### 窗口 1 — 启动 echo Expert Agent

```powershell
$env:PYTHONPATH='.'
py tests/echo_server.py
```

预期：`Uvicorn running on http://127.0.0.1:9001`

### 窗口 2 — 启动 PostgreSQL

```powershell
docker compose up -d postgres
docker compose ps
# 等待 STATUS = healthy
```

### 窗口 2（续）— 装依赖

```powershell
py -m pip install --index-url https://pypi.org/simple -r requirements.txt
```

### 窗口 2（续）— 配 .env

```powershell
copy .env.example .env
notepad .env
```

编辑项：

```ini
# ↓ 把这一行替换成真 key
AGENTNET_LLM_API_KEY=sk-replace-me

# 其余默认即可：
# AGENTNET_DATABASE_URL=postgresql+asyncpg://agentnet:agentnet@localhost:5432/agentnet
# AGENTNET_LLM_BASE_URL=https://api.deepseek.com/v1
# AGENTNET_LLM_MODEL=deepseek-chat
```

### 窗口 2（续）— 建表 + 灌示例

```powershell

```

### 窗口 3 — 启动网关

```powershell

```

预期日志：

```
INFO  agentnet :: AgentNet Gateway 启动完毕
```

健康检查调度器自动跑（默认核心 30s）。

### 窗口 4 — 验证主入口

```powershell
curl http://localhost:8000/healthz
# {"ok":true}

curl http://localhost:8000/
# 列端点
```

## 4. 测试矩阵（12 项）

| # | SPEC 条款 | 测试动作 | 期望 envelope.code | 关键观察 |
|---|---|---|---|---|
| 1 | §2.3 + §3.1 单步直跳 | 注册 `demo.echo` → POST /chat，query="echo 测试" | **200** | `data.content` 含 `[ECHO]`；echo_server 收到 header `X-AgentNet-Token=st_test`、`X-Caller-Dept=...` |
| 2 | §3.1 fast_route 边界 UNKNOWN | query="无匹配意图" | **404** | `message` 含 "无可用 Agent 匹配该意图" |
| 3 | §3.1→§3.2 COMPLEX 路由到 deep_plan | query="先 echo 一段，再 echo 总结" | **200** | `data.steps.length >= 2` |
| 4 | §3.3 占位符注入 | 同 #3 | **200** | `data.steps[1]` 的 agent 子调用 sub_query 含 `[ECHO] ...` |
| 5 | §3.3 2K token 截断 | query="x" * 10000 | **200** | echo_server 收到的 sub_query 长度 < 10000，含 `[... 已被截断 ...]` |
| 6 | §2.2 4xx → 400 | 注册 `demo.bad` 指向 `/api/v1/bad4xx` | **400** | message 含 "downstream 4xx" |
| 7 | §2.2 5xx → 502 | 注册 `demo.fail` 指向 `/api/v1/fail5xx` | **502** | message 含 "downstream" |
| 8 | §2.2 timeout → 408 | 注册 `demo.slow` 指向 `/api/v1/slow`，`timeout_ms=300` | **408** | message 含 "agent timeout" |
| 9 | §5.1 限流 (20 RPS) | `hey -n 100 -c 30 http://localhost:8000/chat -m POST -d @body` | 部分 **429** | message 含 "触发网关限流" |
| 10 | §5.1 熔断 (10s/5 次→60s) | 连发 5 次到 demo.fail 后第 6 次 | **502**, latency≈0 | 第 6+ 次不真调下游，latency_ms 在数十毫秒 |
| 11 | §5.2 健康摘除 | 让 echo /health 返 500，等 ~90s | DB 字段更新 | `SELECT status FROM agents` 显示 `offline` |
| 12 | §6 度量 | 跨部门各跑一次 chat | API 200 | `/metrics/reusability-depth` 中 `cross_dept_saturation_pct > 0` |

## 5. 关键观察点（DB & 日志）

### 5.1 agent_call_logs 计数

```powershell
docker exec -it agentnet-postgres psql -U agentnet -d agentnet -c \
  "SELECT code, count(*) FROM agent_call_logs GROUP BY code ORDER BY code;"
```

期望看到至少这些 code 出现过：

| code | 含义 | 触发项 |
|---|---|---|
| 200 | 成功 | #1, #3, #5 |
| 400 | 下游 4xx | #6 |
| 408 | timeout | #8 |
| 502 | 下游 5xx / 熔断 | #7, #10 |
| 429 | 网关限流 | #9 |

### 5.2 agents.status 检查

```powershell
docker exec -it agentnet-postgres psql -U agentnet -d agentnet -c \
  "SELECT agent_id, status, consecutive_health_failures FROM agents;"
```

期望：
- `demo.echo` → `active`
- 测试 #11 后 `demo.echo` → `offline`（`consecutive_health_failures >= 3`）

### 5.3 日志关键字

```powershell
# 关注这一行，作为 #10 熔断生效的标志
"Agent demo.fail 已被网关熔断 (剩余 60.0s)"

# #11 摘除日志
"Agent demo.echo 连续失败 3 次，置为 offline"
```

## 6. 风险点 & 缓解策略

| 风险 | 缓解 |
|---|---|
| DeepSeek rate-limit 与网关限流混淆 | 限流测试只针对 echo agent，避免误伤 LLM 调用 |
| fast_route 选不中 demo.echo | 用 `"echo 测试"` / `"回显一段"` 这种独特关键词 |
| COMPLEX 触发 deep_plan 不稳 | query 用强提示："先 echo 一段，再 echo 总结" |
| 健康检查摘除需等 90s 太慢 | 临时 `.env`: `AGENTNET_HEALTH_CORE_INTERVAL_SEC=5`，跑完恢复 |

## 7. Mock 路径（无 Docker / 无 key）

若暂时没有 Docker 和 LLM key，可以跑 A 路径快速验证业务逻辑（不含 DB 真落盘）：

```powershell
$env:AGENTNET_STEP_OUTPUT_TOKEN_LIMIT='64'
$env:PYTHONPATH='.'
py tests/test_e2e.py
```

预期输出：`ALL E2E TESTS PASSED` + 12 项标识。

这条路径已在开发期间跑通，输出结果见 README 的"测试"章节。

## 8. 与现有 mock 路径差异对比

| 维度 | Mock (`tests/test_e2e.py`) | B 路径（本文档） |
|---|---|---|
| LLM | 假的 fast_route/deep_plan | 真 DeepSeek |
| Expert | 内存 mock invoke | HTTP 真调 echo_server |
| DB | 不写盘 | 真 PostgreSQL |
| 健康 tick | 不跑 | APScheduler 真跑 |
| 限流/熔断 | 单元断言 | 真实并发打 |

B 路径才是 SPEC 完整版。A 路径只能担保业务编排层。

## 9. 一键脚本（计划新增）

`tests/smoke.ps1`（Windows）骨架：

```powershell
$ErrorActionPreference = 'Stop'

# 0) 准备
$env:PYTHONPATH = '.'
$env:AGENTNET_HEALTH_CORE_INTERVAL_SEC = '5'

# 1) 启动 echo
Start-Process py -ArgumentList 'tests/echo_server.py' -PassThru | Out-Null
Start-Sleep 2

# 2) 启动主网关
Start-Process py -ArgumentList '-m','uvicorn','app.main:app','--host','0.0.0.0','--port','8000' -PassThru | Out-Null
Start-Sleep 5

# 3) 跑 12 项
py tests/run_e2e_against_real_server.py

# 4) 收尾
docker exec -it agentnet-postgres psql -U agentnet -d agentnet -c \
  "SELECT code, count(*) FROM agent_call_logs GROUP BY code ORDER BY code;"
```

`tests/run_e2e_against_real_server.py` 把 `test_e2e.py` 里的 mock 换成 `http://localhost:8000/...` 真请求；其它验证逻辑（占位符断言、code 期望）保持不变。

## 10. 验收 checklist

- [ ] `docker compose ps` 显示 `postgres` healthy
- [ ] `curl http://localhost:8000/healthz` 返回 `{ok: true}`
- [ ] `py -m scripts.seed` 不报错；`agents` 表 ≥ 3 行（seed 默认 3 个 demo + 测试中注册的几个）
- [ ] 测试 #1 → #5 全部返回 envelope `code: 200`，`data.content` 含 echo
- [ ] 测试 #6/#7/#8 code 分别为 400/502/408
- [ ] 测试 #9 部分 429
- [ ] 测试 #10 第 6 次以后 latency < 50ms（真不调下游）
- [ ] 测试 #11 后 DB 中 echo agent `status='offline'`
- [ ] 测试 #12 `/metrics/reusability-depth` 返回非空 items
- [ ] agent_call_logs 表行数 ≥ #1~#10 总调用数（异步审计未丢失）

完成以上 10 项即视为 MVP 验收通过。
